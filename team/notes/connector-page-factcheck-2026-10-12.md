# Fact check: Connect Folderbird with Claude and ChatGPT (draft dfed12c)

Checked 2026-10-12 by two independent reviewers. Code facts against folderbird-web main 2972e90; client steps against Anthropic and OpenAI docs (OpenAI pages only via search snippets, egress blocked).

## Folderbird code

- **[wrong]** 'The Allow page lists exactly what the AI can do', followed by the 5-row table (See your devices / Browse / Download / Upload / Run commands ⚠️)
  - Evidence: The page prints one line for each scope the client requested: Views/Connect/Authorize.cshtml:20-23 loops over Model.Scopes, and ConnectController.cs:157-159 fills that from request.GetScopes(). Each line shows a label plus the scope code, and only exec gets ⚠️ (Authorize.cshtml:22). The real labels, from ConnectController.cs:44-52, are: 'See your devices, whether they are online, and their health (system info)' devices:read; 'Browse folders and search for files on your devices' browse; 'Read and download files from your devices' download; 'Create folders and write or upload files to your devices' upload; 'Run commands on your devices' exec ⚠️; 'Stay connected without signing in again (refresh tokens)' offline_access. Claude and ChatGPT request offline_access as well (docs/submissions/claude-connector.md:118,226-227; chatgpt-app.md:54), so the page usually shows a 6th line that the draft leaves out. The draft's 'What it means' column (CPU/memory/disk, same-name file is replaced, destructive commands blocked) is accurate to the tools (McpController.cs:203-285) but does not appear on the Allow page.
  - Fix: Change the intro to: 'The Allow page lists what the AI may do. Here is what each item means:'. Name the rows with the real labels, or make clear they are summaries. Add a row: 'Stay connected without signing in again: lets Claude or ChatGPT renew access without asking you to sign in each time.'
- **[wrong]** Destructive commands (delete, move, format, shut down) are refused until you confirm. Table: 'Anything that deletes, moves, formats or shuts down is blocked until you say yes in the chat'. Safety: 'refused until you confirm the exact command in the chat'
  - Evidence: The basic mechanism is real. Security/DeviceOps.cs:70-75 refuses a command that DestructiveCommands.Classify flags unless confirm_destructive is true. The refusal tells the model to show the exact command and ask (Security/DestructiveCommands.cs:234-238; McpController.cs:224-228). The verb list covers delete, move, format, process kill and shutdown (DestructiveCommands.cs:51-65). But 'Anything' overstates it. The code says the gate is 'FAIL-SAFE TOWARDS NOT DESTRUCTIVE … not a sandbox' and that evasion is possible (-EncodedCommand and similar; DestructiveCommands.cs:21-23). It deliberately misses cmd 'for … do del' (lines 33-35) and Set-Content or '>' overwrites (lines 45-46). The server also cannot check that you said yes: it only checks the confirm_destructive flag the AI sends (McpController.cs:142, :359-366).
  - Fix: 'Commands that delete, move, format or shut down are refused at first. Folderbird tells the AI to show you the exact command and ask before it tries again.' In the table, change 'Anything that deletes…' to 'Commands that delete, move, format or shut down are refused until you confirm them in the chat.'
- **[wrong]** 'Your files stay on your PC… Nothing is synced or stored in the cloud' / 'Folderbird never syncs or stores them. A download only passes through Folderbird'
  - Evidence: A download puts a temporary copy of the file in Folderbird's transfer storage and keeps it for up to 2 hours: Security/DeviceOps.cs:301-305 (BlobRelay.ScheduleDelete(blobName, TimeSpan.FromHours(2))). The tool description says 'a transient copy is kept for up to 2 hours' (Controllers/McpController.cs:257). The submission doc discloses the same thing (docs/submissions/claude-connector.md:106). Uploads pass through storage and are deleted about 2 minutes after the PC pulls them (DeviceOps.cs:851-853). 'Never syncs' is accurate. 'Never stores' / 'nothing stored' is not.
  - Fix: 'Folderbird never syncs your files. When you download one, a temporary copy passes through Folderbird and is deleted within 2 hours. The link works for 15 minutes.' In the intro, change 'Nothing is synced or stored in the cloud' to 'Nothing is synced to the cloud.'
- **[wrong]** Tokens 'renew for up to 14 days only while you use them'
  - Evidence: The refresh token lasts 14 days (Program.cs:131; ConnectController.cs:42). It is rolling: each refresh replaces the old token (Program.cs:126-129 comment, OpenIddict 5.8 defaults, and no Disable* override anywhere in the repo). So the 14 days restart with every use. The Allow page says it correctly: 'renew for up to 14 days of inactivity' (Views/Connect/Authorize.cshtml:28). The Agents page says the connection 'lasts until you disconnect it in the client' (Views/Integrations/Agents.cshtml:29). The draft's wording reads as a 14-day maximum.
  - Fix: 'Access tokens last 1 hour and renew automatically. If you don't use the connection for 14 days, you'll be asked to sign in again.'
- **[wrong]** Every command and file action is logged on your API keys page
  - Evidence: Over MCP, only run_command is audited: Security/DeviceOps.cs:73 (refused) and :76 (run). Those are the only WriteExecAudit calls in DeviceOps. RunRawAsync, used by read_file, download staging, search and system_info, writes no audit (DeviceOps.cs:82-83). Security/AuditLog.cs:25 says ExecAudit 'only covers API/MCP exec'. Only the command name and its length are stored, never the arguments (Security/ApiKeys.cs:337-353). The API keys page shows the last 50 command rows (Controllers/ManageController.cs:132), under 'Recent command activity' (Views/Manage/ApiKeys.cshtml:51,189-190). Browse, search, read, download, write, upload and create-folder actions are not logged there. The Allow page itself claims only commands (Authorize.cshtml:27). docs/submissions/claude-connector.md:106 makes the same incorrect 'every command and file operation' claim, and it is probably where the draft's wording came from.
  - Fix: 'Commands are logged. Every command the AI runs, including refused ones, shows on your API keys page (command name only).' Also fix docs/submissions/claude-connector.md:106.
- **[wrong]** Menu path 'Manage → API keys'
  - Evidence: The site has no 'Manage' menu. When signed in, the top bar shows a person icon with your name, linking to /Manage (Views/Shared/_Layout.cshtml:447). That page is titled 'Account settings' (Views/Manage/Index.cshtml:3,9). It has an 'API keys' row with a 'Manage keys' button (Index.cshtml:130-134), which opens /Manage/ApiKeys, titled 'API keys' (Views/Manage/ApiKeys.cshtml:3,48).
  - Fix: 'Create one on your API keys page: click your name at the top right, then API keys → Manage keys (folderbird.com/Manage/ApiKeys).' In Safety, say 'your API keys page (folderbird.com/Manage/ApiKeys)'.
- **[wrong]** Menu path 'Integrations → AI Agents & MCP'
  - Evidence: The top nav item is labelled 'AI & Integrations', not 'Integrations' (Views/Shared/_Layout.cshtml:430; Views/Integrations/Index.cshtml:2). The sidebar section is 'AI & Integrations' and its item is 'AI Agents & MCP' at /Integrations/Agents (Views/Shared/_DocsSidebar.cshtml:57-59; Views/Integrations/Agents.cshtml:2). The second half of the path is right.
  - Fix: 'see AI & Integrations → AI Agents & MCP (folderbird.com/Integrations/Agents)'
- **[wrong]** The AI Agents & MCP page has setup lines for Claude Desktop config files, Cursor, n8n, OpenClaw and other MCP tools
  - Evidence: Views/Integrations/Agents.cshtml has setup blocks for Claude Desktop (claude_desktop_config.json, lines 33-42), the mcp-remote bridge (line 44) and OpenClaw (lines 46-58). Cursor is not mentioned anywhere in Views/Integrations. n8n is pointed to the REST API, not MCP (Agents.cshtml:128; Integrations/Index.cshtml:23,34).
  - Fix: 'Claude Desktop config files, OpenClaw and other MCP tools can connect with a Folderbird API key … see AI & Integrations → AI Agents & MCP for the setup lines. For n8n and scripts, use the REST API (API Reference).' Either drop Cursor or add a Cursor example to the Agents page.
- **[unverified]** 'Disconnect Folderbird in Claude or ChatGPT settings and access ends right away'
  - Evidence: No OAuth revocation endpoint is configured. Program.cs:114-119 sets only the authorize, token and configuration endpoints, and no revocation code exists anywhere in the repo. Folderbird also has no page where the user can revoke an OAuth connection. Disconnecting relies on the client discarding its tokens; an access token already issued stays valid until it expires (at most 1 hour, Program.cs:130). The Allow page says only 'disconnect in <client> to end it' (Authorize.cshtml:29).
  - Fix: 'Disconnect Folderbird in Claude or ChatGPT settings to end access.' Drop 'right away', or add revocation.
