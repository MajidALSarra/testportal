- OCI Cache facts gathered: Oracle-managed Valkey 7.2, Valkey 8.1 or Redis 7.0.5. Non-sharded mode has 1-5 nodes, and the mode cannot be changed later. Private VCN endpoint only, TLS on port 6379 (Azure uses 6380). CONFIG, ACL, REPLICAOF, MIGRATE, BGSAVE and others are blocked. No AOF, only on-demand backups. $0.0194 per GB-hour per node. Not Always Free. The 2 GB minimum node size is unconfirmed. docs.oracle.com was blocked from the cloud container (HTTP 403), so some facts come from search excerpts.
- Final engine recommendation: Valkey 7.2 or Redis 7.0.5, non-sharded. The code audit superseded the generic first answer, which said Valkey 8.1.
- Connection string template (no secrets): <primary-endpoint-hostname>:6379,ssl=true,user=<user>,password=<password>,abortConnect=false. Without the explicit port the client dials 6380, and without ssl=true it connects in plaintext. Either mistake leaves the app answering 200. The password must contain no commas.
- Sizing: load is about 1.5 Redis ops/s and the working set is under 10 MB. Production: 2 nodes x 2 GB, about $57 a month. Staging: 1 node x 2 GB, about $28 a month.
- OCI Queue does not fit the device command queue. It delivers at least once, so a runcommand could run twice. Messages are capped at 256 KB, while savetextfile can send about 1 MB. Long polls are held for at most 30 s against the app's 60 s. Adopting it would not remove the need for a cache.
- Other risks from the audit: an unplanned failover can lose or duplicate device commands (async replication, no AOF). Queued commands never expire, so a runcommand to an offline device runs whenever it next polls. A failed Subscribe leaks its handler. Pages loaded during a failover get no live pushes until reloaded. Recommended alarms: memory above 70%, CPU, connections, the RedisTimeoutException/RedisConnectionException/RedisServerException log patterns, and the 5xx rate on api/GetCommands.
